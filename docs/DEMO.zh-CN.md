# 演示录制指南

所有正式发布的图片和视频都应来自真实补丁版应用。演示启动器只提供固定的上下文
比例，不会写入伪造的会话缓存。

## 推荐环境

- 使用约 1440 × 900 逻辑像素的 16:10 窗口。
- 选择文字清晰、颜色不过饱和的深色主题。
- 隐藏通知、用户名和私人路径。
- 以 60 fps 录制；正式素材用 `high`，续航演示用 `low`。
- 保留命令块和较密集的文字区域，便于观察直线被引力透镜扭曲的程度。

## 必录镜头

### 黑洞主镜头

```bash
warp-celestial --demo blackhole high 0.85
```

保持 6–8 秒，展示黑洞阴影、光子焦散、多重吸积盘成像和终端内容扭曲。不要裁掉
底部受保护的工作区。

### 太阳主镜头

```bash
warp-celestial --demo sun high 0.75
```

保持 6–8 秒，使米粒组织、太阳黑子、日珥和喷射粒子都能被看见。

### 上下文增长

在完全一致的窗口尺寸下，分别使用 `0.15`、`0.45`、`0.70`、`0.95` 拍摄黑洞。
连续视频应使用真实 Claude Code 会话并展示上下文比例变化；不要把固定档位剪接后
宣称为实时数据。

### Tab 与分屏

在两个 Pane 中运行上下文比例不同的 Claude Code，录制 Tab 切换和分屏焦点切换，
证明窗口效果只跟随当前焦点 Pane。

### 性能对比

对同一场景分别录制：

```bash
warp-celestial --demo blackhole low 0.85
warp-celestial --demo blackhole balanced 0.85
warp-celestial --demo blackhole high 0.85
```

记录硬件、逻辑窗口尺寸、显示器刷新率和实际 GPU 帧耗时。不能只根据风扇声音或
肉眼流畅度推断性能。

## 导出

保留无损或高码率母版。社交媒体优先使用短 MP4，只有平台无法自动播放视频时才
制作优化后的 GIF。最终文件放入 `docs/media/`，更新 README，并在 PR 中写明
录制环境。
